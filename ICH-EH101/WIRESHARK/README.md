PART ONE: UNDERSTANDING NETWORK TRAFFIC

3. What Is Network Traffic?

Network traffic refers to the data moving between devices, applications, and servers over a network.

For example, when a user visits:

http://127.0.0.1:3000

The browser communicates with the Juice Shop server.

This communication involves different types of information, including:

- Source IP address.
- Destination IP address.
- Source port.
- Destination port.
- Protocol.
- Request information.
- Response information.
- Packet size.
- Connection status.

Wireshark allows us to capture and inspect these communications.

Practical example

Imagine a student opens Juice Shop and searches for a product called "apple".

Behind the scenes:

1. The browser sends a request to Juice Shop.
2. The server receives the request.
3. Juice Shop processes the search.
4. The server returns the search results.
5. The browser displays the results.

Wireshark allows us to observe the network communication involved in this process.

---

4. What Is a Network Packet?

A packet is a formatted unit of data transmitted across a network.

Network communication is divided into smaller units so that information can be transmitted and reassembled at the destination.

A packet may contain:

Component| Description
Source IP| Address of the device sending the packet
Destination IP| Address of the receiving device
Source Port| Port used by the sender
Destination Port| Port used by the receiving application
Protocol| Communication protocol, such as TCP or UDP
Payload| The data being transmitted
Packet Length| Size of the captured packet

Example

When accessing Juice Shop locally:

Source IP:      127.0.0.1
Destination IP: 127.0.0.1
Destination Port: 3000
Protocol: TCP

The actual source port may be dynamically assigned by the operating system.

Important: The source and destination IP addresses can both be "127.0.0.1" because the browser and Juice Shop are communicating within the same machine.

---

5. Understanding Network Protocols

A protocol is a set of rules that determines how devices communicate.

Some important protocols students should understand include:

5.1 TCP (Transmission Control Protocol)

TCP is a connection-oriented protocol.

It establishes a connection before transmitting application data and provides mechanisms for reliable delivery.

TCP is commonly used for web communication.

5.2 UDP (User Datagram Protocol)

UDP is a connectionless protocol.

Unlike TCP, it does not establish a connection through a three-way handshake before sending data.

It is commonly used for DNS queries, streaming, and other communication where low latency is important.

5.3 HTTP (Hypertext Transfer Protocol)

HTTP is an application-layer protocol used for communication between web browsers and web servers.

When students access Juice Shop using:

http://127.0.0.1:3000

The application uses HTTP unless the lab has been configured with HTTPS.

5.4 HTTPS (HTTP Secure)

HTTPS uses TLS to protect HTTP communication.

It encrypts application data while it travels between the client and server.

When capturing HTTPS traffic, Wireshark may show connection information and TLS handshake details, but the HTTP request and response contents are normally encrypted unless decryption has been configured.

PART TWO: INTRODUCTION TO WIRESHARK

6. What Is Wireshark?

Wireshark is a network protocol analyser used to capture and inspect network traffic.

It allows cybersecurity professionals to examine packets travelling through a selected network interface.

Wireshark can help with:

- Network troubleshooting.
- Protocol analysis.
- Traffic investigation.
- Identifying suspicious communication.
- Understanding application behaviour.
- Analysing network attacks.
- Investigating potential information exposure.

Why Is Wireshark Important in Ethical Hacking?

An ethical hacker should understand how applications communicate.

For example, a website may appear normal when viewed through a browser, but analysing its traffic may reveal:

- Unencrypted HTTP communication.
- Unusual requests.
- Unexpected server responses.
- Exposed session information.
- Suspicious connections.
- Unexpected data transmission.

Wireshark provides visibility into these communications.

7. Understanding Network Interfaces

Before capturing traffic, students must understand network interfaces.

A network interface is a connection point through which a computer sends and receives network traffic.

On Kali Linux, students may encounter the following interfaces:

Interface| Meaning
"lo"| Loopback interface
"eth0"| Ethernet network interface
"wlan0"| Wireless network interface

7.1 What Is "lo"?

"lo" is the loopback interface.

It allows a computer to communicate with itself.

The loopback IP address is:

127.0.0.1

When students access a locally hosted Juice Shop instance using:

http://127.0.0.1:3000

The communication takes place through the loopback interface.

Therefore, students should capture on:

lo

7.2 What Is "eth0"?

"eth0" is commonly the name of an Ethernet network interface.

It handles traffic travelling through that network interface.

If students access Juice Shop from another computer or VM over an Ethernet network, the relevant traffic may appear on "eth0".

7.3 What Is "wlan0"?

"wlan0" is commonly the name of a wireless network interface.

It handles traffic travelling through the computer's Wi-Fi connection.

Which Interface Should We Use?

For this practical:

Juice Shop Access Method| Interface to Capture
"http://127.0.0.1:3000" on the same Kali machine| "lo"
Juice Shop accessed over an Ethernet network| Relevant Ethernet interface
Juice Shop accessed over Wi-Fi| Relevant wireless interface

Remember: Always select the interface through which the traffic actually travels.

Capturing on "eth0" when the browser is communicating with "127.0.0.1" will generally not show the expected loopback traffic.

PART THREE: INSTALLING AND PREPARING WIRESHARK

8. Installing Wireshark on Kali Linux

Open the Kali Linux terminal.

Step 1: Update the package list

Run:

sudo apt update

This refreshes the available package information.

Step 2: Install Wireshark

Run:

sudo apt install wireshark -y

Wait for the installation to complete.

Step 3: Verify the installation

Run:

wireshark --version

Expected observation:

Wireshark should display its installed version.

Step 4: Launch Wireshark

Run:

wireshark

The Wireshark graphical interface should open.

Important Note About Permissions

If Wireshark cannot capture packets because of permissions, configure packet-capture permissions through the system's supported Wireshark setup.

On Debian-based systems, the installation may ask whether non-superusers should be allowed to capture packets.

If necessary, run:

sudo dpkg-reconfigure wireshark-common

Select the option that allows non-superusers to capture packets, then add the user to the Wireshark group:

sudo usermod -aG wireshark $USER

Log out and log back in for the group change to take effect.

Avoid routinely launching the entire Wireshark graphical interface as root.

PART SIX: FILTERING NETWORK TRAFFIC

12. Understanding Display Filters

When Wireshark captures traffic, it may collect a large number of packets.

Display filters help analysts narrow down the traffic they want to investigate.

A display filter does not delete other captured packets. It only changes which packets are displayed.

For this practical, we will focus on traffic generated by Juice Shop.

12.1 Filter TCP Traffic

Enter:

tcp

This displays TCP packets.

Expected observation:

Students should see TCP communication generated during their interaction with Juice Shop.

12.2 Filter HTTP Traffic

Enter:

http

This displays packets Wireshark recognises as HTTP.

Expected observation:

Students may see HTTP requests and responses if the application is using unencrypted HTTP.

12.3 Filter Traffic on Port 3000

Enter:

tcp.port == 3000

This displays TCP packets where either the source or destination port is "3000".

Expected observation:

Students should see packets associated with communication to or from the Juice Shop service on that port, provided the capture interface and port mapping are correct.

12.4 Filter Requests Sent to Port 3000

Enter:

tcp.dstport == 3000

This displays TCP packets whose destination port is "3000".

12.5 Filter Responses Sent from Port 3000

Enter:

tcp.srcport == 3000

This displays TCP packets whose source port is "3000".

12.6 Filter Traffic from Loopback

Enter:

ip.addr == 127.0.0.1

This displays IPv4 packets involving the loopback address.

Useful Filters Summary

Filter| Purpose
"tcp"| Display TCP traffic
"udp"| Display UDP traffic
"http"| Display recognised HTTP traffic
"dns"| Display DNS traffic
"tcp.port == 3000"| Display TCP traffic involving port 3000
"tcp.dstport == 3000"| Display traffic sent to port 3000
"tcp.srcport == 3000"| Display traffic sent from port 3000
"ip.addr == 127.0.0.1"| Display IPv4 traffic involving localhost
"tcp.flags.syn == 1"| Display TCP packets with the SYN flag set
"tcp.flags.reset == 1"| Display TCP packets with the RST flag set

PART NINE: UNDERSTANDING TCP CONNECTIONS

15. TCP Three-Way Handshake

Before TCP application data is exchanged, a connection is normally established through a process called the TCP three-way handshake.

It consists of three stages:

Stage 1: SYN

The client sends a SYN packet to request a connection.

Stage 2: SYN-ACK

The server responds with a SYN-ACK packet to acknowledge the request.

Stage 3: ACK

The client sends an ACK packet to complete the handshake.

Diagram

CLIENT                         SERVER
  |                               |
  | -------- SYN ---------------> |
  |                               |
  | <------- SYN-ACK ------------ |
  |                               |
  | -------- ACK ---------------> |
  |                               |
  |       CONNECTION ESTABLISHED  |

Why Is This Important?

Understanding the TCP handshake helps analysts:

- Investigate connection attempts.
- Understand normal TCP communication.
- Identify repeated connection attempts.
- Investigate unexpected connection failures.
- Recognise some patterns associated with port scanning.

PART TEN: DNS TRAFFIC ANALYSIS

17. Understanding DNS

DNS stands for Domain Name System.

It translates domain names into IP addresses.

For example:

example.com

may be resolved to an IP address through DNS.

When a user visits a website using a domain name, the system may perform a DNS lookup before establishing the connection.

However, when accessing Juice Shop using:

http://127.0.0.1:3000

DNS resolution is not required because the browser is already using an IP address.

Why Study DNS in This Lesson?

DNS analysis helps cybersecurity professionals understand:

- Which domains a system communicates with.
- How domain names are resolved.
- Unexpected DNS requests.
- Repeated DNS queries.
- Potentially suspicious domain lookups.

PART TWELVE: IDENTIFYING SUSPICIOUS NETWORK ACTIVITY

20. What Should Security Analysts Look For?

Wireshark can help analysts identify network behaviours that may require further investigation.

Examples include:

20.1 Repeated Connection Attempts

A host repeatedly attempting to establish connections may indicate:

- Misconfigured applications.
- Connection problems.
- Automated scanning.
- Other suspicious activity.

20.2 Unusual Port Activity

Unexpected communication with unusual ports may require investigation.

20.3 Unexpected Traffic Destinations

Applications communicating with unknown or unexpected destinations may require further examination.

20.4 Repeated Failed Connections

Repeated TCP resets or failed connections may indicate:

- An unavailable service.
- Network problems.
- Incorrect application configuration.
- Potentially suspicious activity.

20.5 Unencrypted Sensitive Data

Sensitive information transmitted through unencrypted HTTP may be exposed to anyone with suitable access to the traffic.

Important Note

A single packet or unusual connection does not automatically prove an attack.

Security analysts must investigate the surrounding context before drawing conclusions.

PART FOURTEEN: TROUBLESHOOTING

22. Common Problems and Solutions

Problem 1: Juice Shop Is Not Loading

Possible causes:

- Docker container is stopped.
- Incorrect port mapping.
- Juice Shop is not running.

Solution:

Run:

docker ps -a

Identify the container and start it:

docker start juice-shop

Verify the port mapping:

docker ps

Then visit:

http://127.0.0.1:3000

Problem 2: Wireshark Is Not Capturing Traffic

Possible causes:

- Wrong interface selected.
- Insufficient capture permissions.
- No traffic generated.

Solution:

1. Stop the current capture.
2. Select "lo" if using "127.0.0.1".
3. Restart the capture.
4. Refresh Juice Shop.
5. Generate more application traffic.
6. Confirm Wireshark has the necessary permissions.

Problem 3: Students Cannot See HTTP Traffic

Possible causes:

- The application is using HTTPS.
- The wrong interface is selected.
- The capture began after the traffic occurred.
- Wireshark did not recognise the traffic as HTTP.

Solution:

1. Confirm the URL begins with "http://".
2. Confirm students are capturing on the correct interface.
3. Generate fresh traffic.
4. Try:

tcp.port == 3000

If necessary, inspect the TCP stream and verify the application protocol.

Problem 4: Students Are Capturing on "eth0" but Cannot See Juice Shop Traffic

Explanation:

If the browser accesses Juice Shop through:

127.0.0.1

the communication travels through the loopback interface.

Solution:

Select:

lo

Start a new capture and refresh Juice Shop.

Problem 5: Wireshark Shows TCP but No Readable HTTP Data

Possible causes:

- The application uses HTTPS.
- The relevant packets have not been captured.
- The protocol has not been correctly dissected.
- The traffic is encrypted.

Solution:

Verify the protocol and the URL used by the browser.

Remember that encrypted HTTPS application data is not normally readable without the appropriate TLS decryption setup.

Problem 6: "lo" Is Not Available

Check the interfaces using:

ip addr

You should normally find a loopback interface named "lo".

If it is down, try:

sudo ip link set lo up

Reopen Wireshark and check the available interfaces.

Wireshark is an important tool for understanding and analysing network communication.

During this practical, students used OWASP Juice Shop as a laboratory target and examined the traffic generated by normal application activities.

They learned how to:

- Identify network interfaces.
- Capture local network traffic.
- Apply Wireshark filters.
- Inspect HTTP requests and responses.
- Understand TCP communication.
- Examine DNS traffic.
- Recognise potential information exposure.
- Identify suspicious network behaviour.
- Save and document packet captures.

The key lesson is that network communication contains valuable information about how applications operate.

Understanding this communication helps ethical hackers and security analysts investigate application behaviour, identify potential weaknesses, and understand how attacks may interact with network services.
