1. Introduction

Wireshark is an open-source network protocol analyser used to capture, inspect and analyse network traffic.

It allows security professionals to examine packets travelling across a network and understand how different devices and applications communicate.

In ethical hacking, Wireshark helps penetration testers understand the network communication generated by web applications, identify exposed information and investigate suspicious traffic.

In this practical session, we will use OWASP Juice Shop as our target application and Wireshark to examine the network communication between the browser and the application.

3. What Is a Network Packet?

A network packet is a formatted unit of data transmitted across a network.

When information travels across a network, it is divided into smaller units for transmission.

For example, when a student opens OWASP Juice Shop, several network communication processes may occur:

- DNS resolution, if a domain name is used.
- TCP connection establishment.
- TLS negotiation, if HTTPS is used.
- HTTP requests and responses.
- Additional API requests generated by the application.

Wireshark allows us to inspect these communication processes.

4. What Is Wireshark?

Wireshark is a packet analyser used to capture and inspect network traffic.

It supports protocols such as:

- TCP
- UDP
- DNS
- HTTP
- HTTPS/TLS
- ICMP
- ARP
- DHCP
- FTP
- SSH

It is commonly used by penetration testers, network administrators and security analysts.

5. Understanding the Wireshark Interface

Wireshark has three major viewing sections.

A. Packet List Pane

Displays captured packets in rows.

Common columns include:

- No.: Packet number.
- Time: Capture timestamp.
- Source: Source IP address.
- Destination: Destination IP address.
- Protocol: Detected protocol.
- Length: Packet size.
- Info: Brief packet description.

B. Packet Details Pane

Displays the selected packet's protocol structure.

For example:

- Frame information.
- Ethernet information.
- Internet Protocol information.
- Transmission Control Protocol information.
- Application protocol information.

C. Packet Bytes Pane

Displays the raw packet data in hexadecimal and ASCII representations.

This allows analysts to examine the underlying data carried by a packet.

6. Understanding Network Protocols

A. Ethernet

Provides communication between devices on a local network.

B. IP

Handles logical addressing and routing of packets.

C. TCP

Provides reliable, connection-oriented communication.

D. UDP

Provides connectionless communication without TCP's delivery guarantees.

E. DNS

Translates domain names into IP addresses.

F. HTTP

Enables communication between web clients and servers.

G. TLS

Protects transmitted application data through encryption.

7. TCP Three-Way Handshake

TCP establishes a connection using three steps.

Step 1: SYN

The client requests a connection.

Step 2: SYN-ACK

The server acknowledges the request.

Step 3: ACK

The client acknowledges the server's response.

The connection is established.

Client                 Server
  |                       |
  |------ SYN ----------->|
  |                       |
  |<---- SYN-ACK ---------|
  |                       |
  |------- ACK ---------->|
  |                       |
  |   Connection Ready    |

This is important when investigating connection establishment and failed connections.

8. Installing Wireshark on Kali Linux

Open the terminal:

sudo apt update

Install Wireshark:

sudo apt install wireshark -y

Launch:

wireshark

If prompted about non-root packet capture permissions, enable the appropriate capture permissions for your user and log out and back in if required.

Avoid running Wireshark as root unnecessarily.

PRACTICAL SESSION

9. Practical Exercise One: Prepare OWASP Juice Shop

Objective: Prepare the target application and identify its network connection.

Step 1: Start OWASP Juice Shop

If using a local Docker installation:

docker start juice-shop

If the container has a different name, check:

docker ps -a

Start the appropriate container.

Step 2: Verify the target

Open the browser and visit:

http://127.0.0.1:3000

You should see the OWASP Juice Shop homepage.

Step 3: Identify the target address

For this exercise, the target is:

127.0.0.1

This is the loopback address, meaning the application is communicating locally with your machine.

Important: Traffic to localhost may use the loopback interface rather than your Ethernet or Wi-Fi interface.

10. Practical Exercise Two: Capture Juice Shop Traffic

Objective: Capture network traffic generated when interacting with Juice Shop.

Step 1: Open Wireshark

Launch Wireshark.

Step 2: Identify the loopback interface

Look for an interface named:

- "lo"
- Loopback: lo
- Any other available loopback capture interface.

Select the loopback interface.

If it is unavailable, check your packet capture permissions and interface configuration.

Step 3: Start capturing

Double-click the loopback interface.

Wireshark should begin capturing packets.

Step 4: Generate application traffic

Return to Juice Shop and perform these activities:

1. Refresh the homepage.
2. Search for a product.
3. Open a product.
4. Navigate through different pages.
5. Register a dedicated test account.
6. Log in using that test account.

Step 5: Return to Wireshark

Stop the capture.

You should have captured network traffic generated by your interaction with Juice Shop.

Expected observations

Depending on your setup, you may see:

- TCP communication.
- HTTP requests and responses.
- API communication.
- Application data.
- Connection establishment and termination.

11. Practical Exercise Three: Analyse HTTP Traffic

Objective: Understand how Juice Shop communicates with the browser.

Apply this display filter:

http

Look for HTTP packets.

Select a packet and expand:

- Hypertext Transfer Protocol.
- Transmission Control Protocol.
- Internet Protocol.

Examine:

1. Request method.
2. Request URI.
3. Host header.
4. Source IP.
5. Destination IP.
6. Response status code.

Important: If Juice Shop is accessed through HTTPS, the application data will be encrypted and the HTTP filter may not reveal its contents. For this lesson, use the local HTTP address shown above.

12. Practical Exercise Four: Analyse Product Search Traffic

Objective: Investigate the network requests generated by the Juice Shop search function.

Step 1

Start a fresh capture on the loopback interface.

Step 2

Open Juice Shop.

Step 3

Search for a product, such as:

apple

Step 4

Return to Wireshark.

Apply:

http

Look for requests involving:

/rest/products/search

The exact request path may vary with the application version.

Step 5

Select the relevant request.

Examine:

- HTTP method.
- Request URI.
- Query parameters.
- Host.
- Response status.
- Response content, where visible.

Step 6

Search for another product, such as:

orange

Compare the two requests.

Questions

1. What HTTP method was used?
2. Which endpoint handled the search?
3. Where was the search term transmitted?
4. Did the request URI change?
5. What differences did you observe in the responses?

13. Practical Exercise Five: Analyse TCP Connections

Objective: Understand the TCP connections established when Juice Shop is accessed.

Apply:

tcp

Look for packets associated with:

- SYN
- SYN-ACK
- ACK
- FIN
- RST

To isolate SYN packets:

tcp.flags.syn == 1

To identify reset packets:

tcp.flags.reset == 1

Examine the source and destination ports.

For a typical local Juice Shop installation, the application listens on port 3000.

You can filter traffic involving that port using:

tcp.port == 3000

Questions

1. Which port is Juice Shop using?
2. Which port is the browser using?
3. What is the purpose of SYN?
4. What does SYN-ACK represent?
5. What happens when a TCP connection is closed?

14. Practical Exercise Six: DNS Traffic Analysis

Objective: Understand DNS resolution when accessing Juice Shop through a domain name.

If Juice Shop is configured with a local hostname, generate a DNS lookup for that hostname.

Alternatively, use an authorised domain pointing to your own lab.

Start a capture and execute:

nslookup your-lab-domain

Apply:

dns

Examine:

- Source address.
- Destination address.
- Query name.
- Query type.
- DNS response.
- Resolved IP address.

Note: Accessing "127.0.0.1" does not require DNS resolution. Do not expect a DNS query simply from visiting the localhost address.

15. Important Wireshark Display Filters

Display filter| Purpose
"tcp"| Display TCP traffic
"udp"| Display UDP traffic
"http"| Display HTTP traffic
"tls"| Display TLS traffic
"dns"| Display DNS traffic
"arp"| Display ARP packets
"icmp"| Display ICMP packets
"tcp.port == 3000"| Display TCP traffic involving port 3000
"ip.addr == 127.0.0.1"| Display traffic involving localhost
"tcp.flags.syn == 1"| Display TCP packets with SYN set
"tcp.flags.reset == 1"| Display TCP reset packets

16. Practical Exercise Seven: Investigate HTTP Security

Objective: Understand the security implications of transmitting information over HTTP.

Using the local Juice Shop instance:

1. Start a new capture.
2. Visit Juice Shop.
3. Register a dedicated test account.
4. Log in using the test account.
5. Stop the capture.
6. Apply the "http" display filter.
7. Locate the login request.
8. Examine the request headers and body.

If the application uses unencrypted HTTP, the login request may expose submitted credentials in the captured application data.

Observe this only with your own dedicated test account.

Security implications

Unencrypted HTTP does not protect transmitted application data from network observers who can capture traffic along the communication path.

HTTPS uses TLS encryption to protect application data in transit.

This demonstrates why HTTPS is essential for websites handling authentication and other sensitive information.

17. Understanding Suspicious Network Behaviour

Wireshark can help investigate:

A. Unusual DNS Queries

Repeated requests to unfamiliar domains may warrant investigation.

B. Port Scanning Patterns

Repeated connection attempts to different ports may indicate reconnaissance.

C. Unusual TCP Connections

Unexpected connections or repeated resets may indicate suspicious behaviour or network problems.

D. Unencrypted Sensitive Information

Sensitive information transmitted over HTTP may be exposed to network observers.

E. Unexpected Outbound Traffic

Unfamiliar external connections may require further investigation.

These indicators do not independently prove malicious activity. Additional evidence and context are necessary.

18. Saving the Packet Capture

After completing the practical:

1. Stop the capture.
2. Select File.
3. Select Save As.
4. Use the filename:

Juice-Shop-Wireshark-Analysis.pcapng

5. Save the file in your practical lab folder.

The PCAPNG file preserves the captured traffic for later analysis.

Remember that packet captures may contain credentials, session tokens and other sensitive information. Keep them private.
